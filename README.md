# 发生发展逻辑模型（ODL）——运行时配置纪律层

## 一句话

面向 Agent 输出纪律与长程一致性的运行时配置（纪律层）——以 System Prompt / skill 为加载形态之一：不重写模型、永远不可能与模型同等复杂，只辅助稳定释放已有能力并检验输出（保留长处、补齐短处）。（优化模型参数性质的约束检验）

## 问题

Agent 长程任务的输出偏移；多句复合消息的子句遗漏与顺序错乱；回答型与用户动机不匹配；缺来源与边界声明；输出长度与 token 无节制。

## 方法（四步）

发生（句型三型＋多句拆分→分类统计→逻辑整理→最可能的要求；四类＝问候/情感/事实陈述与解释/功能实现）→ 发展（时空树与位置：时间维主次、跨对话锚点制、三档篇幅）→ 应用（按类回应；事实＝唯物史观（真实性落点）＋真实来源；功能＝递归分解至问题清楚＋先覆盖再精炼＋不可行给替代与止损）→ 自检（5＋1 条）。

## 证据状态（v7 三臂实测）

46 题（SimpleQA 官方抽样 30＋自拟 16）；A 裸调用／B 加载手册 v2.4／C 等长中性 placebo；deepseek-chat、deepseek-reasoner、deepseek-v4-pro；裁判盲评；z 检验＋95% 置信区间：

* 来源引用率 **+67.8pp**（7%→75%，CI 显著）
* 边界声明率 **+36.7pp**（2%→38%，CI 显著）
* 要素覆盖严格率 **+19.0pp**（→100%，CI 显著）
* placebo 无效应（C≈A）；无副作用（正确率无显著变化、零编造、裁判分持平）
详见 数据摘要\_v7.md。
