# 一页概述：发生发展逻辑模型（ODL）

一句话：面向 Agent 输出纪律与长程任务一致性的轻量约束层——一个校准型 System Prompt/skill，不重写模型，只保留长处、补齐短处。

问题：Agent 长程任务的输出偏移；多问题复合请求的子问题遗漏与顺序错乱；回答型与用户动机不匹配；缺边界声明与来源；输出长度与 token 无节制。

方法（四步）：发生（怎么来的：四类＝礼貌问候/情感需求/事实评价/功能实现）→ 发展（时空树与位置：时间维主层＝同一条消息内多问题之间的逻辑发展，次层＝跨对话锚点制（先记锚点、需要时再完整分析）；空间维＝主题分棵不串题；位置＝三档篇幅；主次原则贯穿）→ 应用（四类分别回应：问候情感得体、事实评价客观并注意直接间接违法回答、功能实现目的导向；递归分解至目的达成，效率与 token 是优化指标）→ 自检（输出前八项核对）。

与现有方案的区别：校准型——首次加载输出出入对照表（哪些已在执行/哪些新增/哪些冲突），此后随测试收敛；不覆盖模型原生安全政策。

证据状态：手册v2.2（含英文版全文）＋24题组合题库v4（全部通用、0领域题；对标五公开协议：SimpleQA/TruthfulQA/FActScore/IFEval/MT-Bench；混合采样160次调用；deepseek-chat裁判盲评、同族偏见披露；A/B数据已生成——预声明判据1通过：来源标注率+25pp、边界声明率+12pp、档位声明0→28%、输出长度-55%，全部结果指标无显著变化＝零副作用；详见 数据摘要_v4.md）＋附录E示例。

为什么给 Harness：Harness 是 Agent 核心调度层；本模型是调度层输出纪律的一个可注入模块；生态已有第三方 skill 先例（skill-injector-plugin、superpowers-dsh 等）。
